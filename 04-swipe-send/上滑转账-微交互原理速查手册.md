# 上滑转账微交互原理速查手册

> 配套源码：同目录的 `index.html` 及 `motion.js`、`renderer.js`、`receipt.js`。零第三方依赖，双击用浏览器打开。加上 `?preview` 会自动播一遍。

手机屏幕逻辑尺寸 `390×844`。上滑满行程大约是屏高的 `0.108`，也就是 91px。手指要走满行程的 1.75 倍，按钮才会抬到顶。发送飞行 2.10 秒。回执前 0.52 秒是折射，之后换成真正的界面。

---

## 一、画面是怎么叠起来的

| 层 | 谁负责 | 做什么 |
| --- | --- | --- |
| 环境 | `.scene` | 玫红渐变。窄屏时去掉手机壳，铺满屏幕 |
| 光场 | `renderer.js` 的全屏三角形 | 确认、发送、回执三个相位，全靠两个 uniform：相位和进度 |
| 确认页 | `.review` | 头像、金额、三行明细、滑轨和按钮。抬起量写在 `--lift` |
| 发送文案 | `.sending-label` | 「正在向林悦转账」。用 `clip-path` 从左往右写出来 |
| 回执光栅 | `receipt.js` | 先把勾、金额、收款人画进一张 390×446 的图 |
| 回执界面 | `.swipe-receipt__content` | 折射结束后才显示。按钮这时才能点 |

没有 WebGL 时，光场退成三态径向渐变，回执直接显示界面，手势本身还在。

## 二、时间轴

播放时钟在 `motion.js` 的 `advance()`。确认页的 `progress` 是按钮抬起 0–1。发送页把经过时间除以 2.10 交给着色器。回执页把经过的秒数直接交进去。

| 经过时间 | 画面 |
| --- | --- |
| 上滑中 | 按钮按阻力曲线抬起。拉过 1.2 倍行程才咬合，退回 0.96 以下才松开 |
| 松手，未过线 | 约 0.25 秒弹回。提示保持「继续上滑」 |
| 松手，已过线 | 0.15 秒内补到顶，然后进入发送 |
| 发送 0–0.50 秒 | 确认页淡出并模糊。光箭点火 |
| 发送 0.06–0.70 秒 | 文案从左往右写完 |
| 发送 0.13–0.47 | 青色残影出现又消失。峰值大约在 0.24 |
| 发送 2.10 秒 | 切到回执 |
| 回执 0–0.52 秒 | 光栅图被折射环拆开红绿蓝。界面本体先藏起来 |
| 回执 0.45–0.86 秒 | 顶部摄像头圆点淡入 |
| 回执 1.50–2.18 秒 | 勾从浅紫 `#e4daf5` 变到薄荷 `#8beff5` |
| 回执 5 秒 | 停住，等用户点「完成」 |

`prefers-reduced-motion: reduce` 时，过线松手直接到完成态，不再飞行，也不再折射。

## 三、五个核心做法

### 1. 后半段越拉越沉

手指行程 `pull` 以按钮满行程为单位。按钮抬起是：

```text
u = clamp(pull / 1.75)
lift = 1 - (1 - u) ^ 1.75
```

起点斜率是 1，手指和按钮一样快。末端斜率归零，手指还在走，按钮几乎不动。拖拽时再用临界阻尼跟上 `lift`，所以中途改方向也有重量，不是生硬贴着手指。

### 2. 过线才咬合，而且有回差

咬合线在手指行程 `1.2`。松开线在 `0.96`。过了线会多送进 0.035 的抬起，按钮像卡进一个槽。没退回 0.96 以下，不会因为手抖取消。过线的那一帧用 `exp(-25t)` 做一次短促压扁。

没过线松手：

```text
x = 22 * elapsed
lift = start * (1 + x) * exp(-x)
```

大约四分之一秒回到原位。不要把上滑动画倒放，倒放没有重量。

### 3. 光箭是算出来的

`renderer.js` 的发送相位不贴箭头图。箭身是两段圆头笔触：翼和柄。笔触宽度、噪声褶皱和拖尾都跟着进度 `p` 变。刚起飞时，一道青色残影落在箭身后面，大约从 `p = 0.13` 亮到 `0.47`。文案的露出和这同一个时钟绑定，不另起一条无关动画。

### 4. 回执先画成图，再折射，再换成真界面

勾、金额、收款人、日期和「完成」先画进一张图。前 0.52 秒，片元着色器把屏幕上的点反解回这张图，红绿蓝在波峰两侧错开采样，所以字会被拉开。环过去之后立刻换成 DOM，按钮才能获得焦点。勾的变色是另一段 0.68 秒，不和折射叠在同一瞬间。

### 5. 看不见就停

页面隐藏、滚出视口或离开页面时停掉 `requestAnimationFrame`。拖到一半被打断，按没过线松手处理，不会卡在半空。WebGL context 丢失后丢掉 program，恢复时重新编译；回执在这期间直接显示界面。

## 四、8 条确认手势检查清单

| # | 维度 | 推荐做法 | 避免的坑 |
| --- | --- | --- | --- |
| 1 | **行程** | 后半段越拉越沉，满确认要明显多于按钮自身的高度 | 手指走多少按钮走多少，没有分量 |
| 2 | **门槛** | 过线和松开用两条线，过线后再送进一点点 | 一个阈值来回抖，松手意图不稳定 |
| 3 | **回弹** | 没过线用弹簧回到原位，大约四分之一秒 | 把上滑动画倒放，或瞬间跳回 |
| 4 | **发送光** | 用时间和进度算光箭，文案露出绑在同一条钟上 | 贴 GIF，字和光各播各的 |
| 5 | **残影** | 只在起飞的一小段出现，然后让箭身自己走 | 残影全程跟着，分不清主次 |
| 6 | **回执** | 先光栅、再折射、0.5 秒内换成可点击的 DOM | 折射层一直盖着，完成按钮点不到 |
| 7 | **降级** | 减少动态效果时直接到完成态；WebGL 失败仍能看懂三态 | 降级之后手势也没了，或黑一块 |
| 8 | **生命周期** | 不可见就停帧；中断拖拽按取消处理 | 后台继续跑着色器，或卡在半抬起 |
